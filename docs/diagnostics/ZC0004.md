# ZC0004 — Mixed MaxEntries Values

**Severity:** Warning

Two or more cached methods on the same interface set different non-zero `MaxEntries` values. The generated proxy does not give each method its own bounded cache. All methods with `MaxEntries > 0` that do not use HybridCache share **one** isolated `MemoryCache`, and its `SizeLimit` is the first non-zero `MaxEntries` in declaration order. Each entry counts as size 1, so the limit is a combined entry count across those methods. Every other `MaxEntries` value on the interface is ignored.

`MaxEntries = 0`, the default, is not counted as a different value. The diagnostic is reported once, on the interface. The message names the value that is actually used.

---

## Example

```csharp
// ZC0004: SizeLimit is 500 for both methods; MaxEntries = 10_000 is ignored
public interface IProductRepository
{
    [Cache(TtlMs = 60_000, MaxEntries = 500)]
    ValueTask<Product?> GetByIdAsync(int id, CancellationToken ct);

    [Cache(TtlMs = 60_000, MaxEntries = 10_000)]
    ValueTask<Product?> GetBySkuAsync(string sku, CancellationToken ct);
}
```

`GetByIdAsync` and `GetBySkuAsync` together hold at most 500 entries, not 500 and 10,000.

---

## How to fix

**Option A — Use one `MaxEntries` value** for the whole interface, sized for the combined number of entries:

```csharp
public interface IProductRepository
{
    [Cache(TtlMs = 60_000, MaxEntries = 10_000)]
    ValueTask<Product?> GetByIdAsync(int id, CancellationToken ct);

    [Cache(TtlMs = 60_000, MaxEntries = 10_000)]
    ValueTask<Product?> GetBySkuAsync(string sku, CancellationToken ct);
}
```

Or set it once on the interface:

```csharp
[Cache(TtlMs = 60_000, MaxEntries = 10_000)]
public interface IProductRepository
{
    ValueTask<Product?> GetByIdAsync(int id, CancellationToken ct);
    ValueTask<Product?> GetBySkuAsync(string sku, CancellationToken ct);
}
```

**Option B — Split the interface** when the methods really need separate limits. Each interface gets its own proxy and its own isolated cache.

> **Note:** Do not remove `MaxEntries` from only some methods to silence the warning. An interface that mixes `MaxEntries > 0` methods with `MaxEntries = 0` methods on `IMemoryCache` does not currently compile. See [#180](https://github.com/ZeroAlloc-Net/ZeroAlloc.Cache/issues/180).

---

## When to suppress

Never. If one shared limit is what you want, set every `MaxEntries` on the interface to the value in effect. The behavior is the same and the warning goes away, and the code no longer suggests per-method limits that do not exist.
