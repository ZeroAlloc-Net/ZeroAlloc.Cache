# ZC0005 — [Cache] Ignored on an Uncacheable Return Type

**Severity:** Warning

A method carries its own `[Cache]` attribute, but it does not return `Task<T>` or `ValueTask<T>`. Only those two return types hold a result the generated proxy can await and store. Examples of other return types are `void`, `Task`, `ValueTask`, a synchronous return such as `Product`, `int?` or `List<T>`, and `IAsyncEnumerable<T>`. The proxy forwards such a method straight to the inner implementation, so **the method runs on every call** and the attribute has no effect.

ZC0005 is reported on the method's `[Cache]` attribute. It fires only for a `[Cache]` placed on the method itself. When `[Cache]` sits on the interface, methods that cannot be cached are forwarded without a warning, because an interface-level policy is expected to cover commands such as `SaveAsync` as well as queries.

---

## Example

```csharp
public interface IProductRepository
{
    // ZC0005: returns 'Product?' synchronously; caching is not applied
    [Cache(TtlMs = 60_000)]
    Product? GetById(int id);

    // ZC0005: returns 'Task', which has no result to cache
    [Cache(TtlMs = 60_000)]
    Task RefreshAsync(CancellationToken ct);
}
```

---

## How to fix

**Option A — Return `ValueTask<T>` or `Task<T>`** when the result should be cached:

```csharp
public interface IProductRepository
{
    [Cache(TtlMs = 60_000)]
    ValueTask<Product?> GetByIdAsync(int id, CancellationToken ct);
}
```

**Option B — Remove `[Cache]`** from methods that should not be cached, such as commands. They are forwarded to the inner implementation either way:

```csharp
public interface IProductRepository
{
    Task RefreshAsync(CancellationToken ct);
}
```

---

## When to suppress

Never. The attribute on that method does nothing, so removing it is always the correct fix and leaves the behavior unchanged.
